<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → browser storage | next-themes writes a `theme` string to localStorage and toggles a class on the portal `<html>`. |
| portal ↔ public layout | The provider must NOT cross into the public layout tree (D-01). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-04 | Information Disclosure | theme localStorage value | accept | Stored value is a non-sensitive `"light"`/`"dark"`/`"system"` string; no PII, no patient data — consistent with the portal "zero patient data to third parties" boundary. |
| T-13-05 | Spoofing/Tampering | theme cookie/class | accept | Theme state is cosmetic; tampering only changes the user's own color scheme. No auth or authorization decision depends on it. |
| T-13-06 | Elevation (scope leak) | provider mounted too high | mitigate | Provider mounted ONLY in app/(portal)/layout.tsx; acceptance gate greps app/[locale] for 0 ThemeProvider imports (Pitfall 4). |
| T-13-SC | Tampering | npm installs | accept | No install in this plan; next-themes already in tree (framer-motion install is plan 13-03). |
</threat_model>
