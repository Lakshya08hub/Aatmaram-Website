## Component Inventory

### 1. ImageUploadControl (new, reusable)

Replaces the plain URL text input on doctor, department, and facility CRUD forms (Sheet + react-hook-form + Zod pattern). Also used in the portal Media / Site Images section for the hero background.

**States:**

| State | Visual |
|-------|--------|
| Empty (no image) | Dashed border zone, upload icon (lucide `ImagePlus`), "Click to upload or drag and drop" label, hint text below (accepted types + max size) |
| File selected (pre-upload) | Image preview (object-fit: cover, same aspect as target), filename + size label, "Upload" primary button + "Cancel" ghost button |
| Uploading | Progress bar (accent fill) below preview, spinner on button, button disabled |
| Upload success | Full preview with "Replace" and "Remove" icon buttons overlaid (top-right corner of preview) |
| Existing image (edit mode) | Same as upload success — show current image from stored URL with "Replace" and "Remove" options |
| Error — wrong type | Destructive inline message: "Only JPG, PNG, or WebP files are allowed." |
| Error — too large | Destructive inline message: "File exceeds 5 MB limit. Choose a smaller image." |
| Error — upload failed | Destructive inline message: "Upload failed. Please try again." Retry button (ghost). |

**Interaction flow:**
1. User clicks zone or "Choose file" button → native file input opens (accept="image/jpeg,image/png,image/webp").
2. Drag-and-drop also accepted — zone border flips to accent color on dragover.
3. On file select: validate type and size client-side immediately; show error or preview.
4. Preview shown before upload commit; user must click "Upload" to post to Server Action.
5. On success: preview stays, replace/remove controls appear; react-hook-form field value set to returned public URL.
6. "Remove" triggers a confirmation inline prompt (no modal): "Remove image? This cannot be undone." with "Remove" (destructive) + "Cancel" (ghost) — inline below the control, not a Dialog.

**Aspect ratios by context:**
- Doctor photo: 1:1 (square), 200×200px display in control preview.
- Department image: 16:9, 320×180px display in control preview.
- Facility image: 16:9, 320×180px display in control preview.
- Hero background: 16:9, 320×180px display in control preview (full-bleed on public site).

**Accessibility:**
- File input has `aria-label="Upload image"`.
- Drop zone has `role="button"` + `tabIndex={0}` + keyboard Enter/Space triggers file dialog.
- Progress bar uses `role="progressbar"` with `aria-valuenow`, `aria-valuemin`, `aria-valuemax`.
- Preview `<img>` alt text: "{entity name} image" or "Hero background image".

### 2. DoctorCard (updated)

Current: circular initials avatar (w-20 h-20 blue-100 bg).
Updated: if `photo_url` is set, render `next/image` in the same 80×80px circle with `object-cover`. If `photo_url` is null/empty, preserve existing initials avatar exactly — no visual change for records without a photo.

```
photo_url present → <Image src={photo_url} width={80} height={80} className="rounded-full object-cover" alt="{name}" />
photo_url absent  → existing <div> with initials (unchanged)
```

### 3. DepartmentCard (updated)

Current: 48×48 icon circle (w-12 h-12 blue-50 bg with lucide icon).
Updated: if `image_url` is set, render `next/image` above the card header in a 16:9 container (rounded-t-xl, full card width, height ~160px). Icon circle preserved as fallback when `image_url` is absent.

### 4. FacilityCard (updated)

Same pattern as DepartmentCard. 16:9 header image when `image_url` set; icon fallback when absent.

### 5. Homepage Hero (updated)

Current: plain bg (`bg-brand-nav` / dark navy section).
Updated: if `hero_image_url` is set in `hospital_info`, render as CSS background-image with `object-cover` behind a dark overlay (`bg-black/40`) to keep text contrast. Fallback: current plain `bg-brand-nav` when unset.

### 6. Portal Media Section (new page or section)

Location: portal nav, under a "Media" item (or within Settings > Hospital Info — planner decides exact placement; either is acceptable under this contract).

Contents:
- Section heading: "Site Images" (text-xl semibold).
- One card: "Homepage Hero Background".
  - Shows current hero image preview (16:9, full card width) or an empty state (`components/ui/empty-state.tsx` — reuse Phase 13 component) when none is set.
  - `ImageUploadControl` below the preview (or replacing it when empty).
- Future slots (testimonials etc.) deferred — no placeholder cards in this phase.
